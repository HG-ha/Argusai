# 数据与执行边界

[文档首页](Home.md) · [安装](Installation.md) · [集成](Integrations.md)

本页说明数据保存在哪里、哪些操作会访问外部服务，以及对话、工具和调度之间的权限关系。它用于帮助使用者配置工作环境，不替代组织自己的数据处理与授权流程。

## 设置与数据目录

应用默认使用当前操作系统用户的应用目录。设置文件是应用目录下的 `settings.json`，默认数据目录是其下的 `data/`，可在设置页调整数据根目录。

| 平台 | 默认应用目录 |
| --- | --- |
| Windows | `%APPDATA%/ArgusAI`；未提供 APPDATA 时尝试 LOCALAPPDATA |
| macOS | `~/Library/Application Support/ArgusAI` |
| Linux | `$XDG_DATA_HOME/argusai`，未设置时为 `~/.local/share/argusai` |

常用数据位置如下，均相对于配置的数据根目录：

| 目录 | 内容 |
| --- | --- |
| `tasks/` | 扫描任务、发现、事件与报告 |
| `assistant_sessions/` | 会话记录及相关工作区 |
| `reverse_jobs/` | 逆向任务、样本与产物 |
| `cases/` | Case 与关联证据材料 |
| `knowledge/` | 知识库与回收站内容 |
| `assistant_cron/` | 定时任务、运行记录与触发状态 |
| `channels/` | 渠道配置、配对与凭据相关数据 |
| `tools/` | 受管工具与运行时 |
| `proxy/` | 代理相关数据 |
| `logs/` | 运行日志 |

路径定义见 [core/paths.py](../argusai/core/paths.py)。备份应包括设置文件和需要保留的数据，不要只复制源码目录。

## 迁移与备份

使用界面提供的数据目录迁移流程，先查看预览，再执行迁移。日志目录不随持久数据整体搬运：Windows 下正在写入的 rotating log 不适合移动，旧日志留在原位置，后续 handler 重新绑定到新位置。

迁移后检查任务、会话、知识库和逆向产物能否打开。跨设备或跨操作系统迁移还需复核外部工具路径、运行时和渠道凭据。Windows 渠道加密使用系统用户环境的 DPAPI，复制加密文件不意味着另一台设备或另一用户可以解密。

删除或清空历史之前，先确认需要保留的证据和报告已经导出。不同模块的归档、回收站和永久删除具有不同语义，具体见对应命令的 `--help`。

## 本地保存与网络请求

本地保存资料不意味着所有功能都离线执行：

| 功能 | 可能接收的数据或访问的服务 |
| --- | --- |
| AI 对话与分析 | 配置的模型端点会接收请求中的提示词、选入上下文的材料和工具结果；多模态输入取决于端点能力 |
| 联网搜索与资料获取 | 搜索服务、所访问的网站或文档地址 |
| 工具与运行时安装 | 软件包源、下载镜像和依赖分发服务 |
| 通信渠道 | 配置的聊天平台与配对目标 |
| 带外验证 | 配置的 OOB 服务；使用公共服务前应确认允许发送的内容 |
| 审计请求 | 选定的、已获授权的目标与外部工具所访问的资源 |

模型、搜索、下载、渠道和 OOB 的配置应分别审核。只分析离线材料时，应在提示词中说明不发主动请求，并使用相应的工具范围与联网设置。

## Agent 如何理解当前工作

悬浮球与完整对话都能利用应用提供的工作上下文。页面路由、当前任务或逆向任务 ID、已打开的助手与沙盒面板状态等由应用传递；Agent 可按需读取应用快照，进一步取得对应任务、代理状态、知识条目或逆向任务资料，协助当前工作。

具体文件、代码片段与请求可通过引用或材料标识补充。应用上下文不等于每一次点击的完整记录，也不意味着所有桌面窗口都被持续发送给模型；实际进入模型请求的内容包括所选上下文与调用工具取得的结果。

## 对话配置的范围

- 对话输入栏的模型选择和自动审批属于当前对话，保存后切换和重开会恢复。
- 设置页的模型端点和新对话默认审批用于初始化配置；已有对话保留自己的选择。
- 内置模型会话保存所选端点的非凭据标识与模型名，实际密钥仍从用户设置读取，不把密钥复制进会话选择字段。
- 选中的端点或模型被移除后，需要在当前对话重新选择可用模型；模型故障回退依照运行时的端点链处理。

## 自动审批与定时任务

当前 GUI 自动审批会自动允许包括高风险工具在内的调用，并让 Agent 自行处理域内决策。关闭时会清空会话的工具自动允许集合，然后重新应用设置中的始终允许项；MCP `permission_key` 等细粒度授权还需另行核对。

CLI 的 `chat --yes` 自动批准符合条件的非高风险普通工具确认，不能理解为仅允许只读，也不能与 GUI 全会话自动审批等同。高风险或标记为不可自动批准的确认仍需交互处理。

定时任务有独立的调度与高风险授权路径。新建独立运行对话的任务会按实现继承来源会话允许的能力；来源授权的变更会影响后续执行。细节与撤销方式见 [自动化](Automation.md)。

这些机制用于控制执行。目标与方法的授权范围仍由使用者确定，批准某个工具不代表批准任意目标或任意后续操作。

## 沙盒、浏览器与宿主机

会话文件工作区和 Python 虚拟环境帮助区分文件、依赖与运行上下文；它们不是完整的虚拟机边界。工具能访问什么，还取决于具体工具、批准范围和宿主机权限。

托管浏览器用于隔离自动化环境；复用真实浏览器登录态时，需要确认账号、数据与目标范围。桌面自动化作用于本机窗口，可能触及当前登录应用的内容。

代理 CA、授权头、Cookie、样本、日志和模型上下文都可能包含敏感信息。不要把它们作为公开 Issue、测试 fixture 或仓库示例原样上传。API 密钥在用户设置中管理，渠道凭据使用单独的加密存储；不要把“某些凭据加密”理解成所有设置文件都已加密。

## 授权工作的一份任务说明

开始前记录目标、允许的身份与环境、时间窗口、请求速率、可用工具、禁止操作和交付要求。对主动扫描、流量改写、动态注入和生产定时任务，明确停止条件与负责人。

需要对外共享时，先导出必要材料并脱敏。证据引用帮助回溯分析来源，正式验收与留存格式仍应满足团队自己的要求。
