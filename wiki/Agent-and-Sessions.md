# Agent 对话、会话与小队

[Wiki 首页](Home.md) · [快速开始](Quick-Start.md) · [自动化](Automation.md)

把目标交给 Agent，让它在 ArgusAI 里完成工作。Agent 会结合当前工作上下文，组织扫描、代理、浏览器、逆向、知识整理和自动化工具；你可以查看进度、证据与结果，随时补充材料或调整方向。本页说明如何从悬浮球或完整对话开始，并让同一项工作持续推进。

## 开始之前

先在设置中配置可用的 AI 端点与模型，确认数据目录。浏览器或逆向任务还需要相应的本机环境；见[安装](Installation.md)和[逆向工作台](Reverse-Workbench.md)。首次任务建议使用一份允许分析的本地文件，先验证材料读取、工具输出和证据保存。

## 悬浮球与 Agent 对话：同一份工作，两个入口

**悬浮球**让你保持在当前工作页面，直接向 Agent 下达任务。助手收起时，它默认出现在应用窗口右下方；点击即可展开对话。在 ArgusAI 窗口中，也可以用 `Ctrl+Shift+A` 展开或收起。拖动悬浮球可改变位置，应用会记住位置。

展开后，在顶部标签栏点击 **+** 新建对话，或切换已有标签继续工作。需要更大的阅读空间时，点击 **最大化助手**；**还原助手**恢复面板尺寸。收起面板后，当前运行仍可继续，悬浮球会显示运行或未读提示。停止任务请使用对话中的停止控制。

侧栏 **Agent 对话**用于集中查看与管理历史：点击 **新建对话**开始新任务，或选择已有记录后点击 **进入对话**。它会打开同一套对话面板，也可以从这里查看该会话的沙盒和运行记录。

两个入口使用同一个会话与标签状态。从悬浮球继续某个会话，再从 **Agent 对话**打开它，历史、待办、模型选择和自动审批仍属于这同一个会话；只有新建或切换到另一个会话时，才使用另一个会话自己的配置。

## 在当前工作页面把任务交给 Agent

你可以在扫描任务、代理、逆向样本或知识页面直接展开悬浮球，说明目标，让 Agent 读取相关状态、调用工具并推进下一步。发送消息时，对话会附带当前应用页面与工作状态摘要；任务详情会带入当前任务，逆向任务详情会带入当前样本任务，知识条目也会带入条目标识与摘要。Agent 还可按需调用工具取得完整结果。

例如，打开一项扫描任务后，在悬浮球对话中输入：

```text
我正在看这个任务，帮我分析并继续下一步。
先读取当前任务、发现和已有证据，区分已确认问题与待核实线索。
围绕本任务已经约定的目标与范围，完成尚缺的验证，更新待办，
把结论、复现依据和修复建议整理成报告，并告诉我结果保存在哪里。
```

Agent 从当前任务定位材料，整理计划并执行工具；你可以继续浏览任务页面，展开对话查看进度，补充测试账号或业务背景。完成后核对报告与证据。逆向场景同样可以说“我正在看这个样本，先分诊，定位关键逻辑并保存分析笔记”，由 Agent 读取当前逆向任务后接着处理。

对于具体代理请求，补充流量编号或方法与 URL，例如“分析代理流量 #123 的认证过程，关联相同接口，保存证据并给出下一步验证计划”。代理页会提供代理运行状态，但当前选中的流量行还不会自动加入对话上下文；给出编号即可让 Agent 精确读取对应请求。

材料也可以直接引用到对话：

- 在会话沙盒的文件预览中选取内容，通过选区问答浮层的 **转入对话**，将文件位置、选区范围和文本一起带入。
- 将应用内沙盒文件拖到悬浮球上，展开对话并加入文件引用。
- 在展开后的输入区添加或拖入文件，或粘贴剪贴板中已有的截图，再说明需要分析的内容。

这些上下文来自 ArgusAI 的页面状态、工具与主动引用的材料。悬浮球位于应用窗口内，快捷键由该窗口处理；它不会持续录制整个桌面或自动读取其他应用的内容。

## 创建一个可继续的工作对话

1. 在当前页面点击悬浮球展开助手，点击标签栏 **+**；也可以从侧栏 **Agent 对话 → 新建对话**开始。
2. 选择原生 ArgusAI 运行时，或已经配置并测试的本地 ACP Agent。若选择项目目录，核对目录与授权范围。运行时绑定在首次发言后锁定；切换运行时应新建对话。
3. 在输入区选择本次使用的模型，按需设置联网与思考选项。
4. 提供任务目标、允许的材料或目标、禁止的动作和预期交付物。
5. 先查看计划和待办，再观察工具步骤、结构化结果与需要你处理的确认卡。

任务示例：

```text
分析我提供的预发布环境 HAR 和 JS 文件。
先整理接口、认证方式和敏感参数，为每条结论记录材料来源。
当前只分析已有文件，不发送在线请求，不修改项目文件。
输出接口清单、待核实线索和下一步验证计划；不要将线索直接认定为漏洞。
```

任务结束时，应能找到简洁的结论、仍未解决的问题、证据来源，以及需要下一次继续的待办。大型工具输出可能以文件或证据引用保存，无需把整份原始内容塞进对话正文。

## 模型和自动审批的范围

| 入口 | 影响范围 | 后续行为 |
| --- | --- | --- |
| 对话输入栏的模型选择 | 当前对话 | 保存后可在切换、重新打开时恢复，不修改其他对话或全局端点优先级 |
| 对话输入栏的自动审批 | 当前对话 | 保存该对话的审批状态，不同步开关其他对话 |
| 设置页的“新对话默认自动审批” | 新对话的初始值 | 已有对话保留各自状态 |
| 设置页的端点、模型清单与凭据 | 可供会话使用的全局连接配置 | 会话选择从启用的端点与模型中取得；删除或停用已选连接后需重新选择 |

原生会话会优先使用该会话选择的模型，并保留配置允许的端点故障回退机制。模型服务不可用、鉴权失败或模型被移除时，先查看错误与端点配置，避免反复发送相同请求。

当前版本的会话自动审批会自动批准工具调用，包含高风险工具，并让 Agent 根据证据处理决策后继续。开启前应确认工作范围和可用工具；它和设置中的“新会话默认自动允许（extension）”是不同的授权面。关闭自动审批后，工具级允许列表仍按已有设置和会话授权规则处理。

定时任务有自己的调度与高风险授权，不能用聊天栏开关替代。详见[自动化](Automation.md)。

CLI 的 `chat --yes` 也是独立入口：它自动通过符合条件的非高风险普通工具确认，并非仅限只读工具。标为 `high`、`critical`、`danger` 或带有 `no_auto_approve` 的确认仍需交互处理。它不等同于聊天输入栏中包含高风险工具的会话自动审批；详见[CLI 参考](CLI-Reference.md)。

## 任务进行中如何协作

- 补充材料或纠正方向时，直接在当前对话说明新证据、目标变化和应停止的步骤。明确区分“继续原任务”和“换一个任务”。
- 看到决策卡时，先读正文中的理由，再选择具体选项。需要你判断的业务信息，不应靠自动审批猜测。
- 需要长工作时，让 Agent 维护待办和检查点，把大文件与阶段结果归档。一个清晰的下一步比重复原始任务描述更适合续跑。
- 若要停止当前执行，使用对话中的停止控制。后台扫描、小队成员和定时计划各有独立生命周期，应检查相关面板的状态。

可用于中途纠偏的提示：

```text
暂停当前在线验证。新增的 HAR 显示这个接口需要另一个角色。
先把现有结果保存为证据，更新待办；没有新的授权账号前只分析材料。
```

## 单轮长时间执行与三种持续方式

一个用户任务可以包含多次模型推理、工具调用、结果检查和计划更新。原生 Agent 循环没有固定的模型或工具调用轮数上限；在目标尚未完成、持续取得进展且运行条件允许时，可以按配置推进数十小时级工作。这描述的是执行机制和配置能力，不是本项目已经完成数十小时连续运行的测试声明。

| 方式 | 如何运行 | 适用工作 |
| --- | --- | --- |
| 单轮长时间执行 | 一条用户任务持续进行模型与工具循环，直到完成、停止或遇到执行边界 | 复杂应用审计、多材料分析、连续验证与报告整理 |
| 后台工具任务 | 工具先返回 `job_ref` 收据，真实工作在 Agent 循环之外运行，再查询状态和结果 | 耗时扫描或其他支持后台模式的工具，期间可继续对话 |
| Cron 跨轮续跑 | 按计划再次唤醒对话，读取持久待办与检查点，继续下一步 | 多天调查、长期内网巡检、变更驱动复查和周期演练 |

### 让一项审计在单轮中持续推进

1. 在设置的 **AI 助手工具与安全 → 单次 Agent 最长运行时间** 中核对墙钟上限。原生运行时默认是 **7 天**，提供 12 小时、1 天、3 天、7 天及“不限制”等选项。
2. 按任务规模选择合适上限。配置值 `0` 对应“不限制”，只关闭这一项墙钟边界；取消、循环与无进展保护、工具超时和模型服务限制仍然生效。
3. 在对话中写清目标、材料、授权范围与完成标准，要求 Agent 持续推进尚未完成的待办、归档大结果，并定期保存检查点。
4. 保持应用和宿主机在线，确保模型端点、网络、工具与可用资源能支撑执行。应用退出或电脑休眠会影响运行。
5. 通过工具步骤、待办、阶段产物和日志检查进展。达到交付标准应结束任务；遇到重复失败或证据不足应报告原因。

任务提示示例：

```text
在本轮持续完成这次预发布应用审计。
按已经确认的范围，依次整理接口、检查认证与访问控制线索、完成允许的验证并输出报告。
持续推进未完成 Todo；每个阶段保存 checkpoint 和证据引用，避免重复已完成工作。
目标是交付问题清单、复现依据、修复建议与未覆盖说明，预计可能需要数十小时。
保持在约定域名、身份、请求速率和方法范围内；缺失必要材料或需要人工决策时报告。
```

这里的长运行时间不要求额外反复征求“是否继续原任务”。具体工具授权仍按当前会话与工具策略处理；若已配置自动审批，它的范围仍只属于当前对话。

### CLI 与外部 Agent 的额外边界

`argusai chat` 的 CLI 等待超时默认是 **600 秒**，独立于原生 Agent 的 7 天默认墙钟上限。CLI 长任务需要显式设置覆盖目标时长的 `--timeout`，例如为一次任务设置 48 小时：

```sh
uv run argusai chat --session audit-review --once --timeout 172800 "按该会话待办与检查点继续已授权任务，完成后整理结果"
```

示例中的 `audit-review` 应替换为要继续的实际会话 ID；新 ID 会创建自己的会话。核对该任务实际使用的会话、模型和工具权限。`--timeout` 只调整 CLI 的等待边界，不会扩大授权。ACP 外部 Agent 还受外部运行时自身的会话、超时和资源约束，不能仅凭 ArgusAI 的时长设置推定其可同样长时间执行。

### 后台任务怎样继续

支持后台模式的工具先返回 `job_ref`，表示这次工具调用已返回收据。随后用后台状态工具读取运行状态与最终结果；不要在极短间隔中重复查询，也不要把收据当作扫描已完成。

后台工具任务与完整 Agent 对话有不同生命周期。记录 `job_ref`、原始任务与结果位置，按该工具提供的取消和恢复能力处理；不要假设所有后台任务都会在应用重启后自动恢复。

需要在未来某个时间继续当前工作，或长期重复执行检查时，使用[自动化](Automation.md)，而不是让一个单轮无限等待。

## 文件沙盒与项目目录

每个会话有自己的文件工作区，可保存脚本、报告、截图和中间产物。Python 虚拟环境、Node.js 和 WABT 等工具运行时按需安装；安装需要相应确认，下载会进行哈希或依赖完整性校验。

会话沙盒用于组织文件与运行环境，实际权限仍由工具授权和宿主机决定。读取或修改本地项目时，应明确项目范围。不要因为一个会话正在做审计，就把无关目录、浏览器账号或宿主机环境默认为已授权。

需要交付材料时，可要求：

```text
把最终报告和复现材料整理到当前会话工作区，列出文件用途和证据引用。
移除不需要公开的凭据、Cookie 和个人信息，再提供可交付文件清单。
```

## 保存、关闭与重新继续

会话记录、待办、证据与任务元数据会落盘。重新打开对话后，先确认模型、审批开关和待办是否符合预期，再要求 Agent 根据最近检查点继续。应用重启后的历史可查看，不应据此假设所有进程和浏览器连接仍在运行。

### 编辑、导入与导出对话上下文

在 Agent 对话顶部的会话标签上点击右键，可以选择 **编辑上下文**、**导入上下文**或 **导出上下文**。这里的上下文不是一段附加备注，而是当前会话下一轮会交给模型的对话历史。

- **编辑上下文**以对话形式列出用户与 Agent 消息。每条消息可以单独修改角色和正文，也可以上移、下移、删除，或在任意时候追加新的用户/Agent 消息。
- **导入上下文**支持 ArgusAI 导出的 JSON，以及按 `## User` / `## Assistant`（也支持 `Agent`、`用户`、`助手`）分段的 Markdown。导入后先进入对话编辑器预览，只有点击保存才会改写当前会话。
- **导出上下文**默认生成可再次导入的 JSON；在文件选择器中使用 `.md`、`.markdown` 或 `.txt` 后缀可以导出便于阅读的分段文本。

保存会重写模型可见的会话历史，并根据新消息重新生成会话记忆。原有附件、工具调用和结构化卡片不能在纯文本对话编辑器中无损修改；存在这些内容时界面会显示提示，保存后只保留可见角色与文本。任务、证据、待办和会话沙箱文件不会因此删除。会话正在运行或等待工具确认时，应先停止执行或处理确认，再编辑上下文。

```text
读取本对话最近的待办和检查点，先说明哪些工作已完成、哪些材料仍可用。
继续下一项未完成工作，不重复已完成步骤；遇到失效连接或缺失文件先报告。
```

需要按时间或事件自动唤醒这份工作时，使用固定会话的计划，见[持续续跑](Automation.md#长任务持续续跑)。

## 使用 AGENT 小队

侧栏 **AGENT 小队** 用于持久保存团队、成员和工作房间。每个成员可配置角色、目标、模型、工具范围与授权方式。

1. 先确定可拆分的工作，例如“接口材料整理”“JS 分析”“证据与报告复核”。
2. 建队并检查每个角色的任务与工具范围。成员默认待命，收到命令后开始工作。
3. 用群聊共享任务背景和证据；需要某个成员回应时明确点名或 `@角色`。
4. 用成员私聊处理只应给该成员的信息；不要把群聊与私聊混作同一共享范围。
5. 查看成员状态与阶段结果，核实引用的证据后再合并结论。

小队成员并不需要对每条群聊消息都回应。任务分工应有可检查的产物，避免多个成员重复扫描同一目标、争抢同一浏览器或反复总结相同内容。

示例：

```text
建立三个角色：接口整理、JS 分析、证据复核。
前两个角色只读我提供的材料，不发送网络请求。
证据复核只校验结论与出处，最终由主 Agent 合并待办和报告。
```

桌面与 CLI 可以访问同一小队房间。命令行入口见[CLI 参考](CLI-Reference.md)。
