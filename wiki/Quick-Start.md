# 快速开始

[Wiki 首页](Home.md) · [安装](Installation.md) · [命令行](CLI-Reference.md)

把目标交给 Agent，让它在 ArgusAI 里完成工作。你可以从当前页面的悬浮球开始，也可以在 **Agent 对话**中集中管理任务。Agent 结合工作上下文组织工具，你查看进度、证据和结果，并在需要时补充信息。

这条路线先让 Agent 完成一次离线材料分析，再体验当前页面协作与本地 Web 检查，确认模型可用、工作可继续、结果可保存。

## 开始前

- 已安装发行包，或按[安装指南](Installation.md)完成源码依赖与前端构建。
- 已准备可访问的 AI 端点与模型；只使用不含企业敏感信息的测试材料。
- 为工作资料选择一个本地数据目录。配置、会话、任务和证据会按各自类型保存。

使用发行包时，从桌面入口启动。源码环境在仓库根目录执行：

```sh
uv run argusai --gui
```

如果看到终端控制台而不是桌面窗口，确认命令包含 `--gui`。交互终端中裸运行 `argusai` 默认进入 ops 控制台。

## 第一步：配置模型

打开设置中的 AI 端点配置，填写服务地址、协议、模型和所需凭据，再测试连接。服务地址应是模型服务要求的 API 地址；模型标识应与端点实际提供的模型一致。

先使用非敏感短消息检查响应。连接成功说明端点可以响应这次测试；后续工具调用、长上下文和多模态能力仍取决于模型及端点配置。

如果希望使用本地或内网模型，可以配置相应端点。源码安装不会附带一个可直接使用的大模型。

## 第二步：创建一个离线分析对话

点击应用窗口中的 **悬浮球**展开助手，再点击顶部标签栏 **+** 新建对话。悬浮球默认位于右下方，可以拖动；在 ArgusAI 窗口中按 `Ctrl+Shift+A` 也能展开或收起。需要更大空间时，使用面板上的 **最大化助手**。

另一入口是侧栏 **Agent 对话 → 新建对话**；已有记录可点击 **进入对话**继续。两个入口打开同一套会话，收起面板可以继续浏览工作页面，不会因此停止正在执行的任务。

选择运行时和模型。原生助手可以直接使用已配置的 AI 端点；ACP 运行时需要先准备对应的本地 Agent。

聊天栏的模型选择与自动审批只对当前对话生效。设置页的默认自动审批用于初始化新对话，不会批量覆盖已有对话。初次体验可以保留逐次确认，观察工具请求和结果。

准备一份不含密钥的小材料，例如文本文件：

```text
测试应用采用 Cookie 会话。
前端通过 GET /api/profile 读取当前用户资料。
本材料未提供响应头、服务端代码或运行环境。
```

将文件作为附件加入对话，也可以拖入展开后的输入区，然后输入：

> 只分析我提供的材料，不发送网络请求。整理已知的认证方式、需要补充的信息和后续检查计划；每项结论标明依据，不把信息不足的线索写成已确认漏洞。

预期结果是材料摘要、证据来源和待核实问题。这个例子不包含足以确定漏洞的证据，合理结果可以是“还需补充哪些资料”。

## 第三步：查看过程与保存结果

展开工具步骤，检查读取了哪些文件、输出了哪些材料。需要确认时，先看工具名称、参数和影响范围，再决定是否执行。

让 Agent 将重要结果整理为案例、证据或知识条目，并在会话沙盒中保存一份分析笔记。再次打开该会话，确认记录与模型选择仍然可见。

预期可以找到对话记录，以及实际创建的笔记或证据。聊天中的总结和归档文件应相互对应；没有生成文件时，不应仅凭“已保存”的文字判断归档完成。

完整操作见[Agent 与会话](Agent-and-Sessions.md)。

## 在工作页面继续交给 Agent

扫描、代理、浏览器、逆向、知识整理和自动化都可以围绕同一个目标由 Agent 组织。你可以保持在当前页面，通过悬浮球交代下一步，让它关联已有材料、执行工具、整理结果。

例如，在一项扫描任务的详情页展开悬浮球，输入：

```text
我正在看这个任务，帮我分析并继续下一步。
读取当前任务和证据，整理发现与待办，在本任务约定范围内补齐验证。
完成后生成报告，列出复现依据、修复建议和保存位置。
```

发送消息时会带入当前应用页面和工作状态；当前任务或逆向样本任务可由页面标识定位，Agent 再用工具读取详情。分析具体代理请求时，补充流量编号或方法与 URL，例如“帮我分析流量 #123 并关联相同接口”。当前选中的代理流量行不会自动带入。

查看文件时，可将沙盒文件拖到悬浮球上引用，或在文件选区问答浮层点击 **转入对话**。截图可粘贴到展开后的输入区。这里传递的是应用上下文与主动提供的材料，悬浮球不会持续查看整个桌面。

## 可选：用 CLI 完成相同的离线任务

在源码环境中准备一个测试文件：

```sh
uv run python -c "from pathlib import Path; p=Path('build/quickstart'); p.mkdir(parents=True, exist_ok=True); (p/'note.txt').write_text('Authentication: Cookie session. Endpoint: GET /api/profile. No response headers supplied.', encoding='utf-8')"
uv run argusai chat --session quickstart-offline --once --file build/quickstart/note.txt "仅分析附件，不发起网络请求；列出事实、证据与待核实问题。"
```

`--once` 运行一轮后退出；`--session` 指定保存和复用历史的对话 ID。此命令需要模型端点，网络限制指目标探测不联网，模型请求仍会发送到已配置的端点。

希望在同一对话继续讨论时：

```sh
uv run argusai chat --session quickstart-offline
```

## 可选：检查一个本地测试页面

这一步让 Agent 串起建站、检查与报告，实际请求只发往自己的本机测试服务。可以在当前对话中直接输入：

```text
在当前会话工作区创建一个简单的静态测试页面，用本机可用环境
启动仅绑定 127.0.0.1 的 HTTP 服务，选择可用端口。
用 ArgusAI 对该页面执行 headers 检查，读取报告并解释结果。
保存报告与分析笔记，最后关闭本任务启动的测试服务。
如果本机缺少必要运行时，请明确说明缺什么。
```

查看 Agent 使用的地址、工具步骤和报告路径，再继续到[Web 审计与代理](Web-Audit-and-Proxy.md)。如果也想熟悉命令行，可按以下方式手动完成同一检查。

先创建一个简单页面：

```sh
uv run python -c "from pathlib import Path; p=Path('build/quickstart-site'); p.mkdir(parents=True, exist_ok=True); (p/'index.html').write_text('<h1>ArgusAI local test</h1>', encoding='utf-8')"
uv run python -m http.server 8000 --bind 127.0.0.1 --directory build/quickstart-site
```

保持该终端运行，在另一个终端执行：

```sh
uv run argusai scan http://127.0.0.1:8000 --checks headers --out build/quickstart-scan
```

预期终端显示实际的运行目录与报告路径。打开其中的 `report.html`，核对发现是否能关联到响应头。简单测试服务器可能缺少常见安全头；这些发现应结合应用环境解读。

`--out` 是扫描输出的基目录，具体运行目录以命令返回的 `run_dir` 为准。它不是 GUI 任务 ID。

按 `Ctrl+C` 停止测试服务器。后续可继续阅读[Web 审计与代理](Web-Audit-and-Proxy.md)。

## 常见卡点

| 现象 | 先检查 |
| --- | --- |
| 桌面提示前端文件缺失 | 源码环境是否已运行 `npm --prefix argusai/webui run build` |
| 对话没有模型响应 | 端点、模型名称、凭据和网络；运行 `uv run argusai doctor` 查看诊断 |
| 工具要求安装 Python、Node.js 或 WABT | 这是按需运行时安装；审批前核对工具用途与来源，离线环境需提前准备 |
| 同一对话再次进入时没有预期历史 | 核对 `--session`、当前数据目录和所用用户环境 |
| 代理或设备工具不可用 | 先按对应专题准备 CA、浏览器、外部 CLI 或设备；首次体验可继续使用离线材料 |

更多排查见[故障排查](Troubleshooting.md)。
